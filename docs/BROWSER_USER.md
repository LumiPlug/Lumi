# Browser User：Chrome 插件直连 Lumi

当前方案由 Chrome 插件直接连接已经运行的 Lumi Core。插件使用固定官方身份 `hfhigjgopbjmojflbhhnahpfpnmiaman`；不需要复制 ID，也不再分发或启动浏览器专用 Native Messaging host、独立 adapter、broker 或第二个 MCP server。

## 用户操作

打开 Lumi 设置中的 **Browser User** 只读取真实状态，不会启用功能或打开首次信任登记窗口。

- **安装插件**：在默认浏览器中打开固定官方 HTTPS Chrome Web Store 页面。商店草稿可能尚未发布，以商店页面为准；Lumi 不自动安装插件。
- **检查连接**：用户点击本身是明确的产品授权，允许控制普通 HTTP(S) 网页，禁止项除外；没有配对码、复制配置或额外产品确认页。Chrome 必需权限仍在浏览器内批准。真实 Core 没有已保存信任时，仅此次显式点击打开 120 秒首次登记窗口，成功后保存扩展信任。
- **关闭连接**：连接中或已连接时与检查连接二选一显示，立即停止控制并取消登记窗口；迟到请求不得重新打开。未连接且窗口超时后可再次点击检查连接重试。

已有信任通过认证恢复连接。异常或存在旧信任但未连接时，可选择上下文中的“重新配对”；该破坏性操作仍需确认，撤销本安装的旧信任并保持关闭，之后在可信环境中重新点击检查连接。正常连接不自动重置。

## 网页规则

持久名单只包含用户维护的网页规则，不自动把所有已访问标签页加入名单。每行可原位修改标签、URL 和允许／禁止，保存后才生效。列表固定高度、纵向滚动，说明收在问号提示中；必要错误与真实状态保持可见。

- 未列出的普通 HTTP(S) 网页默认允许；暂停、用户接管与 Chrome 权限限制始终优先。
- 链接按规范化的 origin + pathname 精确匹配，忽略 query 和 fragment，保留尾斜杠；不会扩大到整个域名或路径前缀。
- 不接受 credentials 或非 HTTP(S) 链接。最多 100 条规则，每条 URL 最多 2048 字符，标签最多 120 字符；重复规范化 URL 拒绝保存。
- 旧 `blockedUrls` 无损转为禁止规则。规则写入使用持久 revision 比较，避免 Lumi 的旧草稿覆盖插件刚修改的规则。保存失败保留输入与旧策略；冲突需重新检查最新规则、核对草稿，再保存。
- 禁止规则立即取消旧队列及相关进行中操作；已经派发到网页的输入不能撤回。结果不确定的动作不得自动重放。移除禁止项允许建立新会话，但不会恢复暂停或接管状态。

## 连接与安全边界

Agent → 现有 Lumi MCP → Core BrowserService → 固定 `ws://127.0.0.1:43127/ws` → 官方 Chrome 插件 → CDP。

监听仅在用户开启 Browser User 后创建，固定在 IPv4 loopback。Core 校验 WebSocket 路径、Host 与精确官方扩展 Origin，普通网页来源不允许连接。

首次连接采用 **TOFU（首次使用时信任）**，不是用户核验的强首连认证。无既有信任时，真实 Core 只在用户显式点击连接后的短时窗口内记住扩展；无 pin 的扩展无法独立证明对端是真实 Core 或窗口由用户开启，可能被伪造的本机服务登记。Core 自动恢复即使服务已启用，也不会为无信任状态自动打开登记窗口。已有 pin 不因点击而被替换，后续使用基于已保存信任的双向认证与加密业务传输。取消手工核验后，**无法保证首次登记抵御本机恶意进程抢占端口、伪造对端或主动中间人攻击**。只应在可信本机环境中首次连接或重置信任，不能把 Origin、loopback 或加密本身描述为首连身份保证。

MCP 不能开启功能、手工批准首次信任或写网页规则；这些操作必须经过主窗口宿主认证与明确用户操作。所有连接 Lumi 的 MCP 客户端共享一个控制域，不是多 Agent 身份隔离。不要让互不信任的 Agent 同时控制浏览器。

断线与 Core 关闭停止控制。重连建立新会话，旧 ref、队列和不确定输入不恢复。每次读取和输入操作都校验当前规则与实际 URL；禁止网页的旧标题、URL 不对 MCP 继续发布。`file:`、`chrome:` 等受限页面和跨来源 iframe 不属于默认可控范围。

## 进程与旧版迁移

浏览器功能不增加独立本机进程：使用现有 Lumi 主程序及 Core。系统 WebView 辅助进程、Chrome 自身进程，以及通用 MCP stdio-proxy（按需）应另行计算，不能据此声称整个产品只有一个操作系统进程。

旧 Native Messaging 的启用与网页授权不会自动转为网络监听许可：升级后保持关闭，需用户主动点击连接；该点击授权新范围与短时首次登记。新包不再依赖 Native Messaging 注册或浏览器专用宿主。旧版本可能留下的本用户 Native Messaging 注册不会被静默删除；它们不是当前连接所需。若用户要清理，应使用原安装版本的明确卸载流程，不能盲删未知注册或文件。新界面不再提供旧版注册、路径修复或宿主安装指南。

## 验证限制

单元与合成测试覆盖 UI 请求、规则草稿、并发 revision、短时 TOFU 登记边界、Core 策略与连接边界。Windows release 验收通过真实 WebView → Rust → Core 执行只读 status／diagnose，并打开管理弹窗确认未启用功能或登记；不把它描述为真实 Chrome 首连验收。

实际 Windows／macOS Chrome 的首次权限、TOFU 连接与商店分发仍需对应平台实机验证；以当前提交 CI 和实机记录为准。开发预览的签名、发布及商店可用性不得推定已完成，也不得建议绕过系统安全警告。
