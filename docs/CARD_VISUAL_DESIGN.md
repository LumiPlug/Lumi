# 三类资源卡片视觉方案

本方案为现有卡片的局部视觉设计，使用 impeccable 的 Operate 原则：优先让本机工具、技能与知识库容易识别、比较和打开。面向管理本地 AI 能力的桌面用户，遵循已确认的黑曜石／琥珀、深浅主题、重阴影、4px 控件与 8px 容器、36px 操作目标和统一字阶。品牌原文不改。

## 已实施的数据与状态修正

- 日期显示与排序共享校验；Unix 纪元首秒（0–1000ms）视为已确认占位，回退到真实首次发现时间或未知。只排除已确认异常范围，不随意排除全部旧日期或使用文件修改时间。历史首次发现未知时保持未知。
- 工具在卡片标题行显示现有状态 Badge，草稿与已停用不再依赖齿轮辨识。启用、未启用和归档使用同一状态行。

## 可评审的视觉方案

入口：设置 → UI组件 → 卡片方案（开发环境）。示例数据不读取或修改用户资源，操作只通过现有 Toast 演示。

1. 首行名称与独立动作，工具同时显示状态；名称保留当前单行摘要规则，按钮留足36px。知识库只保留整卡查看入口，不为无按钮的标题行预留按钮高度。
2. 工具与技能标题下方为两行用途，最后一行为左侧类型／软件来源Tag、最右侧可信添加时间。技能不显示启用等状态Tag。知识库维持分支＋版本信息。
3. 中部两行用途，短描述也保留两行高度。缺失描述使用明确说明。
4. 工具与技能内容区域纵向间隔为4px，内边距8px；共用底栏中时间位于最右侧，工具不保留操作数量。知识库底部为文档和节点数量＋更新时间，内部及网格间距维持8px。

预览只组合现有组件，页面 CSS 仅定义网格、间距、位置、截断与对齐。未新增自定义颜色、圆角、阴影、焦点和动效。两种主题、桌面与窄窗口、Tab焦点及独立动作命中均需核验。

### 卡片方案紧凑调整（2026-10-10）

知识库方案的卡片之间和内部纵向间距收紧为8px；无独立操作的标题行不再预留36px按钮高度，使用既有正文行高。复用原有容器密度和字阶，不改控件视觉。该调整先应用于“UI组件 → 卡片方案”预览。

### 工具与技能方案修订（2026-10-10）

按用户澄清：技能卡片不展示已启用等状态Tag，软件来源Tag与归档按钮保留。工具方案为四行结构：首行名称、工具状态和独立动作；第二行来源类型Tag＋添加时间（本机时区，来自工具createdAt）；第三、四行为固定两行介绍，不再另设操作数量底栏。该修订先用于卡片方案预览，示例时间明确标注；业务布局待完整方案评审后应用。

### 已确认卡片方案接入实际列表（2026-10-11）

此前方案仅出现在UI组件预览；本轮按用户要求接入业务列表。工具首行名称／状态／独立动作，第二行来源类型Tag＋工具createdAt添加时间（本机时区，无效值显示未知），第三四行固定两行介绍。技能首行名称和独立归档／恢复，第二行仅软件来源Tag，两行介绍及底部可信日期；不增加启用状态Tag。知识库卡片网格及内部行距8px，按钮内边距8px，保留项目、分支、版本／构建状态、介绍和数量／更新日期的真实语义。所有行为沿用原处理器，共用组件、配色、焦点、主题和重阴影不变。

### 技能与工具卡片底栏及纵向密度（2026-10-11）

按用户最新要求，工具和技能统一为标题／独立动作、两行介绍、最后一行类型Tag（左）与添加时间（最右）。工具状态继续位于标题行，技能仅软件来源Tag。将原独立来源行合并到底栏；各内容区域纵向间隔由12px收紧为4px，保留8px内边距、36px操作目标与现有字阶。实际列表与UI组件预览同步修改，可信日期规则、来源合并、归档恢复、运行审阅和主题行为沿用。
