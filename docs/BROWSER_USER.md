# Browser User 集成边界

用户于 2026-11-02 确认：LumiBrowserMCP 仅交付通用 Chrome 扩展；本地连接、注册和 MCP 能力由 Lumi 软件提供。Lumi 设置新增 **Browser User**，沿用现有 UI 组件，不另做独立适配器安装产品。

## 链路与授权

本地 Agent → 现有 Lumi MCP（HTTP 或已有 stdio proxy）→ Core BrowserService → 本机 IPC → 随 Lumi 分发的 Native Messaging host → 用户授权的扩展标签页 → CDP。

- 不新增第二个 MCP server、桌面程序、托盘或自动启动后台 broker。Native host 只能连接已经运行且已启用 Browser User 的 Core。
- 默认关闭。在设置中点击“安装”，确认固定官方扩展的本用户连接与普通网页范围后启用；无需复制扩展 ID。此操作不安装 Chrome 扩展，用户仍需在 Chrome 中安装扩展并确认权限。MCP 工具不能启用、注册或授予浏览器权限。
- 启用偏好保存在 Lumi 用户目录。Core 重启可恢复已同意的服务设置，但不恢复旧网页会话/ref/队列；仅按最新策略重新接入允许且未暂停/接管的页面。
- 现有 Lumi MCP 是共享凭据、无状态 HTTP。首版明确采用 **同一个 Lumi 控制域**：所有工具操作串行，共享已授权会话，**不是多 Agent 身份隔离**。不得以 HTTP 请求 ID 或每次请求生命周期伪造客户端身份。
- 停用、移除、Core 关闭会中断 native host 并撤销标签页会话。已送达 Chrome 的输入无法撤回；不确定结果标记 `outcome_unknown`，禁止自动重放。
- 注册修复和移除必须通过主窗口宿主认证与用户确认；不得通过公共 MCP token 调用。只清理本项目注册和定位文件，不删除其他客户端配置。

## 状态与验证

Browser User 主操作仅“安装”“检查连接”“关闭”：安装幂等启用并注册或修复本安装连接；检查连接只读，显示人话状态及必要的一句下一步，不倾倒路径、错误码、epoch 或会话明细；关闭停用功能但保留安装，不卸载扩展。已知错误只映射为必要下一步：其他安装需先按旧版流程移除连接，安装包缺失需更新 Lumi，系统权限拒绝需检查授权；未知错误保持通用提示，不展示原始路径或代码，也不覆盖其他安装。注册成功不等于已连接，无连接不显示完整可用。禁止的单个链接在次级名单区管理，不增加模式或域名选择。应用路径变化只有取得明确的同身份维护授权才可自动修复，否则由用户再次点击安装确认。

自动测试覆盖服务队列、取消、断线、协议上限、权限边界、设置动作及平台包构建。真实 Windows/macOS Chrome、首次主机权限、系统鼠标/前台、125%和多显示器由用户实机验收，不能以 CI 替代。

## 迁移与开发版验证

已有独立 LumiBrowserMCP adapter 预览安装时，同名 Native Host 会被识别为其他安装，不覆盖。先退出旧 MCP 客户端，使用旧版自带卸载脚本移除旧宿主，再在 Lumi 设置的 Browser User 中确认注册；不需要把独立 adapter MCP 配置继续保留为新链路。新链路使用已有 Lumi MCP 接入方式，不新增客户端配置入口。

开发预览分发仍为 macOS ad-hoc / Windows 未发布者签名；不得绕过系统警告。当前简化界面不提供卸载或“移除连接”按钮；“关闭”只停止功能，保留本用户注册。macOS 将应用拖入废纸篓也不能保证自动清理注册，完整卸载流程仍需另行明确设计，不声称已自动清理。

本地已运行类型检查、lint、首页契约检查、全套测试和前端/Core生产构建。云端 Unix socket 权限使真实 OS IPC 集成测试明确跳过；CI 不允许此跳过，必须验证 HTTP MCP → Core → 本机 IPC → Native Host → 模拟扩展帧。模拟扩展不是实际 Chrome。完整平台包、Rust 检查/测试及当前精确 commit CI 以 PR 验证结果为准；本机无 Rust 工具链，不声称本机原生构建通过。

官方扩展 ID 固定为 `hfhigjgopbjmojflbhhnahpfpnmiaman`，Chrome 扩展使用用户提供的商店公钥，Lumi 内置同一精确身份。主流程不再要求手动复制 ID；没有私钥生成或提交，也没有执行商店发布。更新 unpacked 开发包后须重新加载并核对固定 ID，旧页面授权不迁移。

首次启用仍需明确确认，之后注册有效的 Core 自动恢复通信服务；扩展自动连接与有限退避重连必须结合已确认的默认允许策略与 Chrome 主机权限。只有 Native Host 收到 Core ready 后才向扩展确认连接。恢复通信可为允许且未暂停/接管的普通网页创建新会话，但不恢复旧 ref 或动作队列，结果未知的输入不重放。

## 默认允许与单链接禁止

用户首次在 Lumi 确认启用时，明确说明普通 HTTP/HTTPS 页面默认允许；扩展另以用户点击申请 Chrome optional host permissions。旧版逐页授权的启用偏好必须重新确认新范围，不静默继承。没有全站/单页两种模式选择，Chrome 未批准权限则不能接入页面。

Browser User 内管理禁止链接。标准化用 URL 的 origin+pathname，移除 query 与 fragment，不扩大到整个域名、不等同尾斜杠。带用户名密码或非 HTTP/HTTPS 链接拒绝；最多 100 条、每条最多 2048 字符。该列表只可由桌面主窗口用户确认维护，不提供 MCP 管理工具。

Core 下发版本化 policy，扩展收到已认证 ready + policy 后才能自动接入；每次读取/点击/输入都校验 policy epoch 和实时 URL。添加禁止链接立即取消队列并停止相关会话；已派发输入不能撤回，不确定结果不得重放。Core 不向 MCP 返回禁页的旧标题和 URL。移除禁项可恢复新会话，但用户的暂停/接管仍优先，不会被导航或重连覆盖。

断线 fail closed，重连按新策略建立全新会话；跨来源导航也建立新会话，旧 ref 无效。Chrome 权限撤销立即停止，受限页面、file/chrome schemes、跨源 iframe 仍不支持。以上代码不代表已在用户电脑授予实际 Chrome 权限，也未执行商店发布。
