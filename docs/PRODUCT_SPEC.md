# Lumi 产品规格

状态：首个可交付版本基线

设置页（2026-10-05）按外观、MCP 连接、首页搭建提示词和 Core 四个水平行呈现。MCP 默认复制当前 HTTP 配置，连接信息与真实自检进入独立详情弹窗；首页搭建提示词复用现有工作助手／功能入口模板及选择偏好，点击即复制并显示只读预览，复制不创建或发布主页。Core 仅显示实际状态和版本，按钮反馈沿用顶部气泡。

## 1. 产品定义

Lumi 是运行在个人电脑上的 AI 经验与能力中心，让不同 AI 软件共享同一套 Memory、标准 Skills 和可执行 Capabilities，并提供一个可由 AI 调整的个人工作台。

Lumi 不提供模型推理，不做聊天软件或 IDE；主页扩展限定为官方工程契约与受限 SDK。

> 标准 Skills 负责指导，Memory 负责沉淀经验，声明式 Capabilities 负责定义连接，Terminal、HTTP、MCP 三种 Runner 负责执行，统一 MCP 对外服务，Artifact 保存结果，Workbench 负责用户展示与操作。

## 2. 产品目标

1. 不同 AI 软件共享个人经验和项目经验。
2. 标准 Agent Skills 可以交付到不同 AI 软件直接使用。
3. 用户或 AI 可以创建 Terminal、HTTP、MCP 三类声明式 Capability。
4. 所有 Capability 统一通过 Lumi MCP 暴露和执行。
5. 用户可以在 Workbench 中直接使用能力，AI 可以修改工作台结构和有限样式。
6. 通过前后端运行、内网 API 报表、Android 编译安装三个真实场景验证产品。

## 3. 核心对象

### 3.1 Memory

Memory 是 Lumi 内置服务，不是扩展。

- Personal Memory：跨项目、跨 AI 软件使用。
- Project Memory：只对指定项目生效，默认保存到项目 `.memory/`。
- Pending Memory：AI 提出的新增或修改建议，用户确认后写入正式 Memory。

Markdown 是内容源，SQLite 保存索引、标签、来源、关联项目和使用记录。

### 3.2 Skills

Skill 采用标准 Agent Skills 目录，至少包含 `SKILL.md`，并可包含 `references/`、`assets/`、`scripts/`。

Skill 是文件交付：Lumi 保存标准目录，通过 AI Client Adapter 复制或链接到各 AI 软件的原生 Skill 目录。Skill 中的脚本不形成 Lumi 的第二套执行系统，需要执行时调用 Capability。

### 3.3 Capabilities

Capability 是保存在 Lumi SQLite 数据库中的声明式记录，其消费者是 Lumi Core，而不是 AI 软件。

AI 只获得 MCP Tool 的名称、说明、输入 Schema 和允许返回的数据；AI 不感知 Runner 类型、固定值和内部执行配置。

Capability 字段使用统一可见性：

- `aiVisible: true`：生成到公开 MCP Tool Schema，通常在调用时由 AI 提供。
- `aiVisible: false`：只由 Lumi 和 Runner 使用，不通过 AI 管理接口或执行结果返回。

不设计独立 Secret 模块。URL、Token、Header、租户字段、工作目录、MCP 启动参数等都可以作为不可见字段保存在 Capability 完整定义中。当前版本的“不可见”是接口可见性规则，不承诺磁盘加密。

AI 可以创建和修改 Capability 草稿，但不能直接启用。用户在 Lumi 中查看完整配置并对整个 Capability 一次性授权；启用后不再对内部工具逐项授权。

### 3.4 Workbench

Workbench 是 Lumi 的展示和操作层，不属于 Runner。

- Capability 返回文本、JSON、日志流、图片、文件或结构化数据。
- Artifact Store 保存需要持久化的结果。
- Workbench 使用内置组件展示结果并调用同一 Capability Registry。
- AI 在官方固定工程中开发 HTML、CSS 和 JavaScript；静态资源经受限加载器运行。

首批组件：操作按钮、参数表单、运行状态、实时日志、Markdown、图片、文件、表格、基础图表和数字指标。

主页采用固定 `index.html`、`app.js`、`style.css` 静态工程，外部 AI 获取与 Lumi 同版本的模板、SDK 和知识库后自由开发，用户无需 Node。其他框架可以输出同样的三个入口文件与静态资源。交付包含静态资源与可恢复源码的标准工程包，主页在隔离容器运行。页面通过 Lumi SDK 调用同一 CapabilityRegistry，不直接访问宿主内部配置。支持导入、MCP 发布、版本检查、源码导出和回滚。完整契约见 [官方主页开发方案](HOMEPAGE_DEVELOPMENT_PLAN.md)。

### 3.5 AI Connections

不同 AI 软件只连接一个 Lumi MCP。Lumi 提供本机 Streamable HTTP Endpoint、stdio 代理入口，以及 Codex、Claude Code、Cursor、Gemini 等客户端的连接和 Skill 同步适配器。

## 4. 三种 Runner

### 4.1 Terminal Runner

默认终端环境与当前用户系统终端的导出环境一致：macOS/Linux 每次启动任务前使用用户默认登录交互 Shell 读取环境（包括 PATH、语言及版本管理器配置），自动 Shell 不再固定为 `/bin/sh`。工具环境变量与外部参数在读取后覆盖；显式 Shell 只改变命令解释器。环境初始化失败须明确报错，不静默退回桌面应用的 PATH。Windows 使用系统 ComSpec 和继承环境。任务仍是非交互后台进程，不提供 TTY、会话别名、函数或终端窗口中的临时变量；Lumi 连接凭据不传入子进程。

用户只配置名称、默认工作目录和 Shell（默认自动识别）。AI 可以提交动态生成的 Shell 命令或脚本。

必须支持 `run`、`start`、`status`、`logs`、`stop`、`restart`。长期任务由 Task Manager 管理，日志使用 cursor 增量读取，停止任务必须终止所属进程组。

Terminal 的 `run` 与 `start` 均无自动运行超时；命令自行退出、手动停止或 Core 退出才结束。相同终端工具再次运行时先停止并等待上一任务退出，再启动新任务，避免并行占用同一端口。环境初始化的 10 秒保护只用于读取 Shell 配置，不是命令运行时限。终端运行窗口只显示日志，合并原日志与结果区的高度；退出码及错误归入日志末尾。

工具运行在独立原生窗口中打开，主窗口仍可继续操作；重复打开同一工具或任务时复用已有窗口。运行中关闭需要选择“结束运行”或“后台运行”，可取消继续查看；结束运行等待任务停止后关闭，后台运行保留任务并可从运行记录独立查看。已结束的任务直接关闭。运行窗口不另启 Core，保留原有授权、停止、日志与参数流程。

### 4.2 HTTP Runner

用户只配置名称、URL、Method、AI 可填写参数、固定字段和允许返回字段。HTTP Runner 使用完整 Capability 组装请求，执行参数校验、不可见字段补充、响应裁剪、超时和错误标准化。

### 4.3 MCP Bridge

支持 stdio 和 Streamable HTTP 上游 MCP，负责连接、握手、工具发现、命名空间、调用转发、长期会话、异常重连和工具列表变化。

外部 AI 永远只连接 Lumi MCP。

## 5. Browser MCP

Browser 不是 Runner，而是使用 MCP Bridge 的预置 Capability。

首个版本内置 Playwright MCP 模板，用户只选择名称、可见/无头和独立/持久会话。Lumi 维护长期上游会话，将工具放入 `browser.*` 命名空间；截图可以直接返回 AI，也可以保存到 Artifact Store。

同时支持粘贴标准 MCP 配置和 AI 创建 MCP Capability 草稿。Chrome DevTools MCP 可先通过自定义 MCP 配置接入。

## 6. 交付模式

### Skill

下载或导入包只是运输格式，安装后必须物化为标准 Skill 目录并交付给 AI 软件。

### Capability

用户表单、AI 草稿、导入文件和未来市场下载包最终都转换成数据库记录。原始导入文件只用于来源、版本和回滚，运行时以数据库、Capability Registry 和 Runner 为准。

### Workbench

保存为数据库中的版本化 JSON 文档，应用重启后保留。主页打开期间每 2 秒读取最新文档；已有主页直接展示内容，用户可通过 AI 使用 MCP 工具调整主页。

## 7. 产品页面

侧边栏默认只显示图标，悬浮或键盘聚焦时显示名称。当前导航：

1. Workbench
2. 工具（内部数据模型仍为 Capabilities）
3. Skills
4. 设置（底部）

Memory 菜单暂时隐藏，保留后续产品规划。工具页按 [工具页功能设计](TOOLS_DESIGN.md) 实施：AI 调用与用户手动运行同等重要，共用配置、整体授权与 Registry。已提供完整配置编辑、AI 可见预览、Terminal／HTTP／上游 MCP 执行、任务停止与运行记录。保存配置修改后重新成为草稿，暂停新调用；已有任务按原配置运行。图片、文件结果与导出留待 Artifact 阶段。

工具内容页采用网格卡片列表，新增与编辑在弹窗内完成。基础配置仅要求名称和必要连接信息；支持中文名称、自动公开标识、默认用户主目录与系统 Shell。HTTP 基础配置默认返回响应状态及文本，MCP 真实发现操作后自动形成参数定义；配置仅提供两步引导内的必要参数，不提供高级设置或旧配置编辑入口。

AI Connections 未来放在设置中；Activity 和错误日志在有真实数据后提供入口。工作台初始页面使用“连接 Lumi → 构建工作台”两步引导：第一步复制连接提示，点击“开始使用”完成自检并检查本次会话中的外部工具访问；第二步点击工作助手或功能入口快捷模板，即刻复制不含连接信息的提示词并在顶部反馈；提示词默认折叠，可按需查看。右下角仅保留“完成”，结束引导后可随时重新进入配置。设置仍提供配置查看、复制与连接自检。HTTP 与 stdio 共用会话令牌，应用重启后需更新配置。AI 通过版本化工程包接口发布主页，SDK调用真实功能。

## 8. 验收场景

### 前后端开发

- AI 启动、停止、重启前后端项目。
- AI 和 Workbench 持续读取运行日志。
- Playwright MCP 打开本地页面并截图。
- 截图作为 Artifact 在 Workbench 展示。

### 内网 API 固化报表

- AI 根据 API 文档生成 HTTP Capability 草稿。
- 用户填写不可见字段并启用。
- AI 调用 API 获取结构化数据。
- 数据保存为带时间和查询条件的快照。
- Workbench 展示指标、表格、图表，并导出 CSV/XLSX。

### Android

- Terminal Runner 执行 Gradle 编译并登记 APK Artifact。
- 使用 ADB 查询设备、安装 APK。
- `adb logcat` 作为长期任务运行。
- Workbench 实时展示、搜索和过滤 Logcat。

## 9. 当前不做

- 实时市场服务、账号、支付、评分、在线审核（Skills 页面提供精选官方来源卡片）。
- Skills/Capabilities 加密和 DRM。
- UI、Browser、Android、Docker、Report Runner。
- 自定义插件代码和任意 UI 注入。
- Capability 内部工具级授权。
- 云同步、团队协作、Scheduler、Webhook Trigger。
- 自带 Chromium 或 CEF。

## Skills 本机目录与资源列表（2026-09-30）

Skills 页面只保留软件来源分类、搜索与刷新一行，移除原“已安装／市场”导航行，“已归档”为软件分类的最后一个 Tab。进入页面自动扫描当前用户的 Codex、Claude Code、Qoder、QoderWork、Cursor、Gemini CLI 标准目录以及已添加项目的标准目录；软件来源表示目录归属，不承诺客户端当前加载或启用。Tab 与搜索区域固定，只有下方技能列表垂直滚动；筛选栏依次为占宽不超过一半、可水平滚动的软件来源 Tab，固定宽度搜索框和用于重新扫描的刷新图标；不展示字段标题和结果数量提示。技能以紧凑三列网格铺满可用宽度，首行为带平台背景色的来源标签、技能标题与归档／恢复图标，下方两行描述；卡片悬停使用主色边框；点击卡片打开左右分栏详情，左侧为技能文件目录，右侧为选中文件预览，默认打开技能主文件。支持 Markdown 排版、文本源码和常见本地图片；来源与状态可展开查看，支持复制选中文件路径。文件读取只限该技能目录，脚本仅展示不执行；窗口缩放时列表宽高自适应，窄窗口降为两列或一列。支持名称/描述/来源/目录搜索及来源筛选。页面不再提供扫描位置及添加项目目录入口；既有项目配置继续参与扫描，不遍历整台电脑。

技能列表默认按真实 `SKILL.md` 文件的创建时间倒序（较新在前），来源筛选、搜索与已归档沿用该顺序。创建时间来自文件系统 birthtime，仅近似表示添加到电脑的时间，不承诺真实安装日期；不使用文件修改时间。无效日期、非正时间及已确认的 Unix 纪元首秒（0–1000ms）占位值均视为未知；显示与排序共用同一标准化规则，缓存读取时立即生效。无法获取有效创建时间时回退到 Lumi 首次收录时间，两者都未知的记录置后；排序时间相同或都未知时按名称、真实路径、ID 稳定排序。每次成功扫描更新文件创建时间并为历史记录补充该值；内容修改和归档／恢复不改变排序时间，文件重建或重新安装后按新文件的创建时间排序。文件缺失或读取失败时保留缓存日期；Lumi 首次收录时间仍保持原值。


技能卡片在两行描述下方靠右显示“添加于 YYYY-MM-DD HH:mm”，采用本机时区与共用 `ui-resource-meta` 字阶，显示时间对应排序所用的文件创建时间。文件创建时间不可用时显示“首次发现 YYYY-MM-DD HH:mm”，不将 Lumi 收录时间标成安装时间；两者都未知时显示“添加时间未知”。悬停说明日期来源，日期与卡片按钮通过辅助技术描述关联；已归档卡片沿用相同规则。只增加元信息布局，不新增控件视觉或效果。

同一物理 SKILL.md 合并来源，同名不同目录保持独立；技能包内标准 `skills/` 子目录中的技能也可发现。归档仅在 Lumi 中收起，可恢复，不修改源软件文件；扫描保留归档状态，归档文件消失后保留上次信息并标记。市场入口已从 Skills 页面移除，当前页面只管理本机技能与归档。

工具新增采用名称/类型/用途与类型配置两步引导；Terminal 支持固定命令和带默认值的外部环境变量，HTTP 支持 Form/JSON Body 与结构化正则返回白名单，MCP 支持可选上游工具名筛选。首页启动和页面桥接等待显示居中 Lumi 呼吸文字。

新增工具表单的滚动区域须保留完整焦点描边；Shell 编辑区以整个容器呈现焦点。高级设置及旧配置编辑器删除，三类配置均直接使用当前引导表单。

MCP 创建 Terminal 草稿支持固定 Shell command 与可选工作目录，AI 可完成可审阅的工具配置；创建不会执行或授权。


## 工具列表与子页面改版（2026-10-02）

工具列表第一行左侧为「全部 / TERMINAL / HTTP / MCP / 已归档」类型 Tab，右侧为新增工具。下一行保留搜索、授权状态筛选和刷新。三列卡片首行依次为类型 Tag、占据剩余空间且超长截断的名称、运行或审阅按钮；第二、三行为两行简介，不再显示底部状态与操作数量。卡片名称提供完整辅助技术名称，点击卡片或键盘 Enter/Space 进入工具子页面；首行独立按钮不会重复触发卡片导航。返回列表保留筛选和滚动位置。

已有工具使用整页子页面，顶部左侧返回与工具名称，未归档工具进入详情后默认可编辑；右上角集中运行、保存、启用（仅未启用时）、归档/恢复操作，移除编辑与禁用按钮。保存后继续可编辑，归档工具保持只读。未修改时保存按钮禁用；未保存修改期间运行、启用与归档禁用，保存仍按现有规则转为草稿。导航包含「基本配置」「工具配置」「运行记录」，固定在内容上方；基本配置显示名称和用途，工具配置显示连接、参数及授权审阅，运行记录显示任务与结果。两个配置 Tab 共用编辑草稿，切换保留输入；离开配置进入运行记录沿用未保存保护，校验失败自动切换到首个错误字段所在 Tab 并聚焦。仅下方内容滚动。运行按钮打开参数与结果弹窗，沿用同一 Core 执行链路。新增工具仍采用两步弹窗。修改未保存时继续使用离开保护；所有操作反馈复用顶部 Toast。

归档为可恢复的持久状态，与停用区分：保留配置及执行记录，归档时停用并从默认列表收起；通过分类末尾的「已归档」Tab 进入查看和恢复，授权状态筛选不再提供归档选项。恢复为未授权草稿，须重新审阅启用；归档不强制终止已有任务。数据库增加 archived 标记，UI API archive/restore 使用版本及更新时间校验，已归档工具不能启用或暴露给 AI，新旧草稿保存均保留现有归档状态。
