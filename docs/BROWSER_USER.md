# Browser User：Chrome 插件直连 Lumi

当前方案由 Chrome 插件直接连接已经运行的 Lumi Core。插件使用固定官方身份 `hfhigjgopbjmojflbhhnahpfpnmiaman`；不需要复制 ID，也不再分发或启动浏览器专用 Native Messaging host、独立 adapter、broker 或第二个 MCP server。

## 用户操作

在 Lumi 设置中打开 **Browser User**。打开弹窗只检查真实状态，不会自动恢复已关闭的连接。

- **安装插件**：在系统默认浏览器中打开固定官方 HTTPS Chrome Web Store 页面。商店草稿可能尚未发布，是否可安装以商店页面为准；Lumi 不会自动安装插件，也不要求用户输入任意链接。
- **检查连接**：实际开启 Core 的浏览器连接。首次及旧版范围不足时，需确认允许普通 HTTP(S) 网页控制，禁止项除外。Chrome 插件权限仍需用户在浏览器中批准。连接尚未完成时会显示“连接中”，并可打开插件完成连接。
- **关闭连接**：与检查连接二选一显示，可在连接等待期间取消；停止浏览器控制、断开连接并清除待配对候选，不卸载插件。关闭后的旧请求返回不会重新启用功能。

未连接且存在旧配对或异常时，可在上下文中选择“重新配对”。确认后只撤销此 Lumi 的配对并关闭连接；再点击检查连接，与插件核对新短码。首次和正常连接不会自动重置配对，也不会把恢复按钮增加为日常主流程。

首次配对时，Lumi 与 Chrome 插件分别显示相同短码。用户须核对后明确勾选确认；批准绑定当时的具体候选、短码和有效期，不会转批后来出现的候选。短码不同、过期或未由自己发起时，不应批准。后续连接使用已保存凭据认证，不重复盲目信任来自相同扩展来源的任意连接。

## 网页规则

持久名单只包含用户维护的网页规则，不自动把所有已访问标签页加入名单。每行可原位修改标签、URL 和允许／禁止，保存后才生效。列表固定高度、纵向滚动，说明收在问号提示中；必要错误与真实状态保持可见。

- 未列出的普通 HTTP(S) 网页默认允许；暂停、用户接管与 Chrome 权限限制始终优先。
- 链接按规范化的 origin + pathname 精确匹配，忽略 query 和 fragment，保留尾斜杠；不会扩大到整个域名或路径前缀。
- 不接受 credentials 或非 HTTP(S) 链接。最多 100 条规则，每条 URL 最多 2048 字符，标签最多 120 字符；重复规范化 URL 拒绝保存。
- 旧 `blockedUrls` 无损转为禁止规则。规则写入使用持久 revision 比较，避免 Lumi 的旧草稿覆盖插件刚修改的规则。保存失败保留输入与旧策略；冲突需重新检查最新规则、核对草稿，再保存。
- 禁止规则立即取消旧队列及相关进行中操作；已经派发到网页的输入不能撤回。结果不确定的动作不得自动重放。移除禁止项允许建立新会话，但不会恢复暂停或接管状态。

## 连接与安全边界

Agent → 现有 Lumi MCP → Core BrowserService → 固定 `ws://127.0.0.1:43127/ws` → 官方 Chrome 插件 → CDP。

监听仅在用户开启 Browser User 后创建，固定在 IPv4 loopback。Core 校验 WebSocket 路径、Host 与精确官方扩展 Origin，普通网页来源不允许连接。首次通过双端短码核对批准，后续使用双向认证及加密业务传输；不能仅凭 Origin 或端口信任本机其他进程。占用端口或认证失败时关闭失败路径，不向不可信端点泄露页面内容。

MCP 不能开启功能、批准配对或写网页规则；这些操作必须经过主窗口宿主认证与明确用户操作。所有连接 Lumi 的 MCP 客户端共享一个控制域，不是多 Agent 身份隔离。不要让互不信任的 Agent 同时控制浏览器。

断线与 Core 关闭停止控制。重连建立新会话，旧 ref、队列和不确定输入不恢复。每次读取和输入操作都校验当前规则与实际 URL；禁止网页的旧标题、URL 不对 MCP 继续发布。`file:`、`chrome:` 等受限页面和跨来源 iframe 不属于默认可控范围。

## 进程与旧版迁移

浏览器功能不增加独立本机进程：使用现有 Lumi 主程序及 Core。系统 WebView 辅助进程、Chrome 自身进程，以及通用 MCP stdio-proxy（按需）应另行计算，不能据此声称整个产品只有一个操作系统进程。

旧 Native Messaging 的启用与网页授权不会自动转为网络监听许可：升级后保持关闭，需用户重新确认范围并配对。新包不再依赖 Native Messaging 注册或浏览器专用宿主。旧版本可能留下的本用户 Native Messaging 注册不会被静默删除；它们不是当前连接所需。若用户要清理，应使用原安装版本的明确卸载流程，不能盲删未知注册或文件。新界面不再提供旧版注册、路径修复或宿主安装指南。

## 验证限制

单元与合成测试覆盖 UI 请求、规则草稿、并发 revision、短码候选绑定、Core 策略与连接边界。Windows release 验收通过真实 WebView → Rust → Core 执行只读 status／diagnose，并打开管理弹窗确认未启用功能；不把它描述为真实 Chrome 配对验收。

实际 Windows／macOS Chrome 的首次权限、配对与商店分发仍需对应平台实机验证；以当前提交 CI 和实机记录为准。开发预览的签名、发布及商店可用性不得推定已完成，也不得建议绕过系统安全警告。
